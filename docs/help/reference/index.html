    Command and interface reference

    CLI, TUI, and command palette

    Use this page to find a command family or terminal-interface action. Run ptrack <command> --help, and then the relevant subcommand with --help, for authoritative arguments and flags in your installed version.

    A hold is separate from status. plan hold and task hold pause an item with a reason, and resume clears it — as does completing the item, since a done task or a done or archived plan clears its hold automatically. The item keeps its own status, so task list --status still filters on todo, doing, done, and blocked only. Held work is skipped by next, listed separately by context, and marked in every read surface.

    Multiple developers on one shared database coordinate through identities and claims. config set user <name> mints a stable per-machine identity once (the name is mutable metadata). plan use claims the plan for the caller and makes it that caller's active plan — the active plan is per-developer, and a machine without a configured identity keeps the old project-wide behavior. Content changes to a plan claimed by someone else are refused; holds, notes, and issue links stay open to everyone as the cross-developer channel. plan release frees a claim, finishing a plan releases it automatically, and plan use --steal takes over a claim (each claim or steal bumps the plan's claim epoch). Claim owners are shown in plan list, the TUI, and the desktop sidebar.

    plan delete <id> --force permanently removes a plan and cascades in one transaction: its tasks and every note on the plan or its tasks are deleted, linked issues survive with their task link cleared (each detached issue is listed), and commit records survive as an unlinked audit trail. Without --force the command only previews what would be destroyed and refuses to delete. plan move <id> --to <project> [--as "<title>"] relocates a plan subtree to another registered project, named by the path or name shown in ptrack projects — an ambiguous name is refused with a prompt to name it by path instead. The move copies into the target and commits that write before deleting the source, so an interruption between those two steps can only ever leave a visible duplicate, never lose the plan; the remedy is plan delete on the unwanted side. A moved task's linked issue travels with it; a copied task's linked issue is duplicated into the target instead. Either way the plan arrives unclaimed, its hold reason travels, and its milestone link is dropped (a milestone groups plans within one project). Moving to the current project is refused — rename it in place with plan rename instead. Commit records travel with the plan too, but a sha the target already holds mints no second record — that commit stays attached only to the original plan, so a same-project copy carries none of the source's commit records. plan copy <id> [--to <project>] [--as "<title>"] duplicates a subtree with freshly minted IDs; copying within the same project requires --as. All three commands are claim-gated like any other content change.

    Order between items is recorded as dependency edges. task dep add <id> <dep-id> makes the first task wait on the second — the two may live in different plans — and plan dep add <id> <dep-id> does the same between plans. dep remove deletes an edge, and dep list <id> (with --json) shows what a record depends on, each entry marked open or done (a dependency is open until its target is done). Self-dependencies, duplicates, unknown targets, and cycles are refused. Like a hold, a dependency never rewrites the dependent's status — openness is computed when read, so holding or blocking a target changes nothing on the records that wait on it. next skips tasks with open dependencies and reports why (skipped: #12 (waiting on #9), or active plan waiting on #2 when the plan itself waits), and context lists waiting work in a project-wide Waiting on dependencies section. Deleting a plan or task strips its ID from every dependency list; plan move and plan copy remap dependencies inside the moved subtree and drop edges whose target stays behind. Items waiting on open dependencies carry a ⛓ marker on TUI board cards and Desktop cards and sidebar rows.

    JSON output

    --json is command-specific, not a global promise. It is documented for only these read commands:

    • milestone list --json, milestone show <id> --json
    • plan list --json, plan show <id> --json
    • task list --json, task show <id> --json
    • issue list --json, issue show <id> --json
    • plan dep list <id> --json, task dep list <id> --json
    • note list --json, commit list --json
    • context --json, next --json, checkpoint --json, search <term> --json
    • board --json, status --json, projects --json

    TUI screens

    Running ptrack without a subcommand opens the terminal interface when the desktop-enabled build is used inside a project. Its five screens are 1 Overview, 2 Board, 3 Milestones, 4 Issues, and 5 Maintenance.

    Command menu↑/k, ↓/j, Enter; direct keys 1–5, g, m, e, M, P, r, B; ?/F1/Esc close.

    Screen-specific keys

    • Overview: ←/h and →/l switch plan/task pane; ↑/k and ↓/j select; a add; n note; u activate plan; x finish plan; s/d/b start/finish/block task; M move; P convert.
    • Board: ←/h and →/l change lane; ↑/k and ↓/j select card; H/< and L/> move status; a task; n note; M move plan; P convert.
    • Milestones: ↑/k, ↓/j, a add, x done, o reopen.
    • Issues: ↑/k, ↓/j, a add, c close, o reopen.
    • Maintenance: uses the global navigation, reload, backup, menu, and quit keys.

    Desktop command palette

    Open the palette with Cmd+K on macOS or Ctrl+K elsewhere. It is a project search surface, not a command launcher. It performs a case-insensitive substring search over plan titles, task titles, and note bodies in the current workspace, returns at most 50 results, and groups them Plans → Tasks → Notes.

    Use ↑/↓ to select, Enter to open, and Esc to close. A plan result opens that plan's Board snapshot. A task result opens its plan's Board and task drawer. A note result opens Overview, where Recent memory is shown.
