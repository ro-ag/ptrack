    Diagnostics and bounded recovery

    Recover without bypassing p-track safeguards

    Start with the narrowest diagnostic, preserve authoritative data and recovery artifacts, and use destructive controls only when their stated scope is acceptable.

    Project and database errors

    “No p-track project found”

    p-track resolves the deepest canonical project root in the attested active-generation marker. Confirm where you are, then change to the registered project:

    pwd
git rev-parse --show-toplevel
cd /path/to/repository
ptrack context

    If this repository has never been initialized, run ptrack init once at its intended root. Do not initialize a different directory merely to silence the error; see Start Here.

    Database busy or read timeout

    Project and global databases wait for their file lock for one second. Let an active p-track operation finish, close an unintended duplicate p-track process that has the same database open, and retry. Do not delete .ptrack/ptrack.redb, global.redb, active-generation.json, or a cutover lock. During migration, preserve the complete journal, handoff, receipt, marker, and legacy files.

    Database format is newer than this p-track

    Install a compatible newer p-track binary and retry. The older binary refuses the database and leaves it untouched. Do not force it open, downgrade it, or attempt a schema edit. Review the documented migration boundary.

    This refusal can also read like corruption. A record written by a newer p-track is reported as an invalid manifest, naming the collection and the two schema numbers:

    invalid database manifest: collection plans requires codec 3 schema 1, found codec 3 schema 2

    Any requires codec … schema …, found codec … schema … message whose found schema is the higher number means exactly one thing: this database was written by a newer p-track, and this binary is the old one. Nothing is damaged and nothing is lost. Upgrade every installed copy of p-track — including the other one you use on this machine — and retry. Do not delete, recreate, or restore the database, and do not edit it; a project database and the global database are both refused whole, so the fix is the binary, never the data.

    The same one-way boundary applies to payload schema 3 (introduced with multi-developer identities and claims). The first write from a schema-3 p-track stamps records with schema 3, and a 0.26-or-older binary then refuses the whole database fail-closed:

    invalid database manifest: collection plans requires codec 3 schema 1..=2, found codec 3 schema 3

    Nothing is damaged and nothing is lost. Upgrade every installed copy of p-track — the CLI, the desktop app, and any copy on a shared machine — and retry. Databases written by 0.25 or 0.26 open unchanged in the new version and upgrade record by record as they are written; there is no manual migration step and no way to write records an old binary accepts again.

    Desktop project and board state

    If Open Project or Switch Project reports active terminals, agent runs, or resource operations, inspect the confirmation instead of repeating the action. Confirming stops the counted resources and cleans up the current project before switching; canceling keeps the current workspace. If the confirmation expires or resources change, start the switch again so p-track can recount them.

    A task transition confirmation is tied to the exact task, status, linked resources, and association revisions shown. If the board says the task or linked resources changed, the status was not updated. Close the stale prompt, refresh the workspace, inspect the current task and live resources, then request the transition again.

    Desktop reopened wrong, or the window is misplaced

    If p-track reopened a project you did not expect, turn off Reopen the last project when p-track starts in Settings ▸ Startup; if it landed on the welcome screen instead, look for the recent entry marked Preselected — that is the project p-track recorded, and it moved, because p-track never opens a relocated project on its own. Confirm its new location yourself with Locate… on it. A window restored onto a display that is no longer connected is recentered on the primary display automatically, so no reset is needed for that case.

    When the sidebar, panels, or window geometry are unusable, use Settings ▸ Data & Diagnostics ▸ Reset Window Layout. It restores the default window and layout immediately and touches nothing else. Reach for Reset Application State only when you accept losing every setting, saved terminal workspace, and network capability grant. Grants live in the project, so revoking them writes to the open project's database and each scope must be granted again before any network access works; plans, tasks, notes, and Recent projects are not touched. Stored window and layout records that p-track cannot read are reported and replaced by defaults in memory, not overwritten, so an unreadable record left by a newer version survives a downgrade.

    Terminal recovery

    Restored tabs and split descriptors start as stopped panes. Opening one creates a new session. The prior process, terminal contents, output, and scrollback are not restored.

    ControlUse it forBoundary
    Restart terminalAn ordinary pane with a failed or exited process or stream.Closes the old session and creates a fresh one.
    Relaunch linked agentA linked-agent pane that stopped.Launch again from its plan or task; ordinary restart is intentionally unavailable so fresh authority can be bound.
    Retry terminal rendererA selected, visible pane using the fallback renderer.Rebuilds rendering without restarting the PTY.
    Force stop terminalA selected current session that cannot stop normally.Requires confirmation and targets that session.
    Reset terminal workspaceA repaired or discarded layout that remains unusable.Replaces the saved layout and terminates every live session represented by the workspace.

    Terminal diagnostics are content-free: they report bounded process, stream, renderer, layout, update-time, retry, and repair state. They do not include terminal output, commands, clipboard text, environment values, credentials, or stream URLs. See terminal diagnostics and recovery.

    Agents, associations, and stale runs

    After a Desktop restart, a previously launched agent is marked stale because its hosting terminal ended and the new process cannot know its outcome. Relaunch it from the intended plan or task. An external agent may resume heartbeats only with its existing lease token; otherwise its lease expires and the run becomes stale.

    • An association provides validated project, plan, or task context. It grants no task, filesystem, network, command, Git, or capability authority.
    • A worktree claim only records a verified, existing host-observed worktree that contains the run's working directory. It does not create a worktree, move the agent, change its CWD, or run Git.
    • A handoff is a bounded proposal and preview. Sending or acknowledging it grants no authority and changes no task or project memory.
    • A workflow proposal remains a proposal when approved. It executes no command, Git or hosting action, task change, or capability grant.

    When one of these actions is rejected as stale, refresh Overview and repeat it against the current live run and association revision. Read the full authority boundary summary.

    Capability denials and connection tests

    A broker call is denied when its grant is missing, disabled, expired, materially edited, for another agent profile, or outside the exact normalized scope. Return to Capabilities, inspect Preview scope, correct the draft if needed, save it, and explicitly enable the exact previewed scope again. Do not broaden the scope merely to make a failing call pass.

    ptrack capability call also requires the broker session token and matching project descriptor supplied inside a p-track-launched agent terminal. Calling it from an ordinary or stale shell fails closed; relaunch the agent from the correct project context instead of copying tokens.

    Test connection is a separate, explicit, non-mutating diagnostic for the draft. Use its normalized error class to check reachability or configuration before enabling a grant. A successful test does not enable the capability, approve a scope, or prove that a later broker call is authorized. See grant lifecycle.

    Updater recovery

    If the updater enters recovery-required state, close p-track and preserve the update state under $PTRACK_HOME/updates or ~/.ptrack/updates. On Linux, keep every .pending-apply-*.json journal with its sibling .ptrack-backup-* executable until the installed target is identified. Settings ▸ Data & Diagnostics reports those paths and the recovery-required status read-only, so you can confirm the state before closing the app.

    Do not delete a journal or backup, and do not copy a staged payload into place. Reinstall the same or a newer package from the official GitHub Releases page as the conservative fallback. The update recovery guide describes the artifacts and platform-specific boundary.

    Frequently asked corrections

    Does selecting a plan in the Desktop sidebar change the CLI active plan?
    No. It changes the Desktop view only. Use ptrack plan use <id> to change the CLI active plan.
    Does p-track check for updates automatically?
    Not by default. Automatic checks remain off until you explicitly opt in from Settings ▸ Updates or About & Updates; a manual check does not silently download or install.
    Does Reset Application State delete my plans or tasks?
    No. It clears settings, the startup and update-check opt-ins, window and layout state, and saved terminal workspaces, and it revokes all network capability grants. Grants live in the project, so revoking them writes to the open project's database; with no project open, nothing is revoked. Plans, tasks, notes, and Recent projects are not touched, and your capability definitions stay authored — re-granting each scope is the part you must redo.
    Are capabilities an operating-system sandbox?
    No. They authorize exact typed broker calls. Ordinary shell processes retain whatever network and filesystem access the operating system gives them.
    Does ptrack backup capture everything, and can p-track restore it?
    No. It copies the project database, not runtime state or WebView localStorage, and there is no built-in restore command. Follow the documented backup limits; this page does not prescribe an unverified restore procedure.
    Are interactive terminal paths verified on every platform?
    No. End-to-end clipboard, shortcut, context-menu, restart, and shutdown acceptance is verified on macOS only. Windows and Linux implementations exist, but this Help Center does not claim those interactive paths passed end to end.
