# Inventory: TUI (Go v0.21.0)

Subsystem: `internal/tui` — the human-facing Bubble Tea dashboard (files: `tui.go`, `view.go`, `detail.go`, `menu.go`, `conn.go`, `theme.go`, `tui_test.go`). Built on `bubbletea` + `lipgloss` + `charmbracelet/x/ansi`. Entry point `tui.Run()`.

## Contracts

### Entry / exit / process behavior

- TUI-001: Running `ptrack` with no subcommand launches the TUI (desktop build: `main.go:36-43` overrides `cli.RunNoArgs` to call `tui.Run()`). In builds without the desktop tag, the same invocation instead prints `ptrack: nothing to do. Run 'ptrack --help' for commands or 'ptrack status' for an overview.` to stdout and exits 0 (`internal/cli/root.go:12,21-25`). — pinned by: none — verify: manual
- TUI-002: Project discovery before launch: walk up from the process CWD looking for `<dir>/.ptrack/ptrack.db`; stop (with `ErrNoProject`) after a directory containing `.git` or at filesystem root (`internal/store/discovery.go:23-44`, called from `internal/tui/tui.go:27-34`). — pinned by: none — verify: automated test
- TUI-003: Outside any project, `ptrack` (no args) prints the exact getting-started hint to **stdout** and exits **0** — no error, no stderr (`main.go:38-41`; hint text verbatim in `internal/cli/hint.go:5-14`: `p-track  ·  persistent project memory`, rule line, `No p-track project here yet.`, `GET STARTED` block listing `ptrack init`, `ptrack init --goal "..."`, `ptrack --help`, and closing `Once a project exists, run \`ptrack\` to open the dashboard.`). — pinned by: none — verify: fixture
- TUI-004: Any other `tui.Run()` error propagates to `main`, is printed to stderr, and the process exits 1 (`main.go:44-47`). Quitting the TUI normally (`q`/`ctrl+c`) exits 0 with no output. — pinned by: none — verify: manual
- TUI-005: Before launching, `store.WriterVersion` is set to the CLI version string so the DB records the last writer (`main.go:24`). — pinned by: none — verify: automated test
- TUI-006: The DB is opened once at startup to validate/migrate, then closed immediately (`internal/tui/tui.go:36-40`); the running TUI never holds the bbolt file lock while idle — every store operation opens and closes the DB (`internal/tui/conn.go:14-21`). - TUI-007: The TUI runs in the terminal alternate screen (full-screen app, `tea.WithAltScreen()` at `internal/tui/tui.go:46`); on exit the previous terminal content is restored. — pinned by: none — verify: manual
- TUI-008: On launch the model loads a full snapshot: meta, milestones, plans, tasks grouped by plan, issues, counts; the plan cursor is initialized to the active plan's position in the plan list (`internal/tui/tui.go:131-143,145-172`). — pinned by: `tui_test.go:TestIdleModelHoldsNoLock` (partial) — verify: automated test

## Notes / surprises

- **Issue creation is title-only from the TUI** (`AddIssue(val, "", "", 0)`, `internal/tui/tui.go:618`): severity defaults to whatever the store does with an empty severity string — the Rust version must reproduce that default, including how an empty severity renders (gray, 8-wide padded blank) in issue rows.
- **`g`/`m` with empty input overwrite (clear) the goal/summary** — unlike adds and notes, edit-goal/edit-summary have no empty-cancel guard (`internal/tui/tui.go:609-612` vs `641-645`). Easy to "fix" in a rewrite and break parity.
- **`q` quits even from the detail panel** (it never just closes the panel; `internal/tui/tui.go:301-302`), and on the welcome screen any unrecognized key is swallowed and keeps the welcome up (`internal/tui/tui.go:291-293`). Both are intentional-feeling but easy to invert.
- **Notes on the Issues tab are silently redirected to project notes** (`internal/tui/tui.go:771-773` comment: "notes don't attach to issues"). The status still says `note added`, so the user gets no signal the target differs.
- **The header's "project name" is derived from the DB path** (`filepath.Base(filepath.Dir(filepath.Dir(dbPath)))`, `internal/tui/view.go:73`) — i.e. the parent of `.ptrack`, not any stored project name; backup filenames use the same derivation (`internal/store/global.go:178-180`).
- Rendering parity risk: the whole visual contract leans on `lipgloss` cell-width/ANSI semantics, a 5-cell block meter with min-1-filled rule (`internal/tui/theme.go:134-151`), multi-stop gradient interpolation, and exact-height fill. Tests pin dimensions and substring content but not exact bytes/colors — a Rust port will need its own golden-output fixtures to be truly indistinguishable.
