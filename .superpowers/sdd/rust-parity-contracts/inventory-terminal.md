## Notes / surprises

- **Stream disconnect destroys the session.** Closing the WebSocket for any reason (even a renderer crash) terminates the shell process (TERM-013). There is no detach/reattach and no server-side scrollback: recovery restores only pane descriptors (TERM-093). A Rust port must reproduce this destructive coupling or deliberately change UX.
- **`terminal:status` is emitted but unused.** The Go backend publishes both `terminal:status` and `terminal:exit` (TERM-065); the frontend subscribes only to `terminal:exit` (TERM-101). The status event is still an observable contract for any other consumer.
- **Profile DTO redaction is asymmetric.** `GetTerminalProfiles` strips executable/args/env/fixedCwd (TERM-060), but the on-disk config file and `MergeProfiles` carry them; the frontend never sees launch-affecting fields, so profile editing UI can only safely touch presentation fields.
- **ACK parser is stricter than JSON.** Duplicate keys, leading zeros, unknown fields, and trailing data are all rejected (TERM-009) — a stock `JSON.parse` on either side would accept frames this implementation rejects. The Rust side needs an equivalently strict parser or the flow ledger can be desynced.
- **Startup buffer stalls output at 64 KiB until attach, and the GUI kills unattached sessions after 30 s** (TERM-020, TERM-021). Creating a session without ever connecting its stream URL is not a way to run a background shell.
- **Doc/code divergence to note:** `docs/tauri-rust-recode.md` defers decisions the acceptance doc treats as stable (e.g. renderer choice); the code behavior above is authoritative. Also, Windows `TerminateJobObject(job, 1)` (TERM-025) means force-killed Windows sessions surface exit code 1 from the job, while unix force-kills surface whatever `wait` reports after SIGKILL — platform-asymmetric exit codes are observable.
- **Shell-integration nonce appears in plaintext in PTY output** (OSC 633 sequences) and in the child env before being unset; it is a correlation token, not authority, but any log capturing raw PTY output will contain it (TERM-057).
- **Untested seams** (code is the only spec): WS URL opacity on the client, xterm constructor assembly (`pane.ts:1578`), search decoration colors, OSC handler registration wiring, dock DOM ids (`#terminal-dock` etc. in `frontend/index.html`), and the `app.js` V1→V2 generation adapter (`app.js:4080-4165`).
