## Notes / surprises

- Registry is in-memory authoritative; `agent-runs.json` is an advisory mirror. A Rust rewrite must preserve the "corrupt/future history never blocks startup, never gets clobbered" behavior and the restore-time migration (launched→stale, associations detached, exit-result reclassification, single normalized rewrite on next sweep) — these are observable across restarts.
- Two different token regimes share one server: external runs use lease tokens returned at registration; host-launched agents use a run-ID-free `/v1/events` endpoint with a pending-token handshake and a 2s bind window. Both fail with distinct, fixed strings (401 `AgentRun lease rejected` vs `AgentRun event token rejected`) — an externally visible distinction.
- `recognizedNotification` is unexported, so notification self-assertion is impossible via JSON — but the same validation path is reused for trusted history restore, which sets the flag from `event.Notification.Valid()` (persistence.go:329). A rewrite must reproduce this asymmetry or notifications will either be forgeable or unrestorable.
- Event retention is enforced lazily at read/sweep/save time, and EventSnapshot/IntelligenceSnapshot mutate (prune+persist) as a side effect of a "read" (registry.go:1003-1011,1046-1054). Observable: totals shrink after retention windows pass.
- HTTP handlers authenticate BEFORE decoding provider-controlled bodies and again at commit; the 413 limit is 16KiB+1 read; `Origin` header presence alone forces 403 — browser-attack fences a rewrite must keep exactly.
- Launch-context redaction is deliberately line-based and conservative (whole line replaced), unlike the event-summary regex redaction (span-based). Two different redaction dialects exist in this subsystem; mixing them up changes output bytes.
- Snapshot sorting tiebreak differs by API: Snapshot sorts LastActivityAt desc then ID asc; WithExactRuntimeSnapshot sorts by ID only. GUI-visible ordering depends on it.
- `classifyExitResult` accepts `session restarted` (with a space) as a stable class — an odd but pinned vocabulary entry.
- The descriptor PID-liveness check is advisory by design (PID reuse); security rests on generation + constant-time token compare at connect and at cleanup. Do not "improve" this into hard failure in a rewrite.
- codex `turn.completed` maps to lifecycle/waiting (not completed) — completion is reserved for explicit session-end; pinned by TestProviderAdaptersReserveCompletionForExplicitSessionEnd.
