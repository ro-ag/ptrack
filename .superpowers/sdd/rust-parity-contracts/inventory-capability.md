# Inventory: Capabilities — network/Git/SSH grants (Go v0.21.0)

Scope: `internal/capability/**` plus the persistence/DTO types it exposes
(`internal/model` capability records, `internal/store/capabilities.go`,
`internal/agentrun` descriptor path) and `docs/ptrack-threat-model.md`.
The Settings Wails API (`internal/gui/capability_settings.go`), token
injection (`internal/gui/terminal.go`, `internal/terminal`), and the
`ptrack capability` CLI bridge (`internal/cli/capability.go`) are separate
subsystem inventories; only the contracts this package imposes on them are
recorded here.

## Contracts

### HTTP scope normalization

- CAP-011: Path prefixes must be absolute, query/fragment-free, unambiguous (same encoding rules as CAP-009), and each must lie within the base URL path on a **segment boundary** (`pathWithin`: equal, or parent `/`, or child has prefix `parent+"/"`); an empty prefix list defaults to `[base.Path]`. — src: internal/capability/normalize.go:190-205,265-278,288-292 — pinned by: TestNormalizeHTTPPathUsesSegmentBoundaries (normalize_test.go:69) — verify: automated test

### Approval digest & lifecycle

Field order is struct order. ### Authorization envelope (repeated at every use)

- CAP-032: `Authorize` runs on every operation and checks, in order: re-normalization succeeds (`stored capability is invalid`); stored digest non-empty and equal to fresh digest (`approval scope is stale`); `Enabled` (`capability is disabled`); exact profile match (`agent profile does not match`); `ApprovedAt`/`ExpiresAt` non-zero (`capability has not been approved`); `ExpiresAt > now` (`capability approval has expired`); `ExpiresAt ≤ ApprovedAt+duration` (`approval expiry exceeds its duration`). — src: internal/capability/policy.go:47-76 — pinned by: TestAuthorizeRejectsStaleProfileDisabledAndExpiredGrants (policy_test.go:45) — verify: automated test
- CAP-033: `AuthorizeHTTP`: kind must be http (`capability is not HTTP`); method uppercased and in approved list (`HTTP method %s is not approved`); body size 0..MaxRequestBytes (`HTTP request exceeds its byte limit`); request URL re-normalized with query allowed but fragment rejected (`HTTP request URL is invalid`); scheme+host must equal base (`HTTP request origin is outside the approved scope`); path must match a prefix segment-wise (`HTTP request path is outside the approved scope`). Query strings are permitted in requests but never enter persisted/audited scope. — src: internal/capability/policy.go:148-191 — pinned by: TestHTTPWriteMethodAndPathRequireExactApproval (policy_test.go:138) — verify: automated test
- CAP-034: `AuthorizeGit`: kind git (`capability is not Git`); operation in allowlist (`Git %s is not approved`); freshly-read remote name and normalized URL must equal scope (`Git remote no longer matches the approved scope`); fetch/pull/push require approved branch (`Git branch is not approved`); non-empty refspec must be allowlisted (`Git refspec is not approved`); force requires `AllowForcePush` (`Git force push is not approved`); leading-`:` refspec requires `AllowDeleteRefs` (`Git ref deletion is not approved`); refspec containing `refs/tags/` requires `AllowTags` (`Git tag writes are not approved`). Empty branch/refspec allowlists authorize none. — src: internal/capability/policy.go:193-235 — pinned by: TestGitReadGrantDoesNotImplyWriteAndRemoteMustStayExact (policy_test.go:157) — verify: automated test
- CAP-035: `AuthorizeSSH`: kind ssh (`capability is not SSH`); each of the 7 operations (`git`, `remote-command`, `upload`, `download`, `interactive-shell`, `local-forward`, `remote-forward`) is authorized independently — no grant implies another; `remote-command` requires exact string membership, forwards require normalized endpoint membership; failures: `SSH %s is not approved`, unknown op `unknown SSH operation %q`. — src: internal/capability/policy.go:34-45,103-146 — pinned by: TestSSHGrantsDoNotCompose (policy_test.go:71) — verify: automated test
- CAP-036: `ResolveProjectPath`: canonicalizes the project root (EvalSymlinks+Abs), requires a project-relative requested path, resolves the target (for non-existent targets the nearest existing ancestor is resolved to defeat symlinked parents), and demands containment in both the canonical project and one approved root. Denial reasons: `project root cannot be canonicalized`, `path is not project-relative`, `path escapes the project`, `path is outside approved roots`. — src: internal/capability/policy.go:237-305 — pinned by: TestResolveProjectPathRejectsSymlinkEscapes (policy_test.go:181) — verify: automated test

## Notes / surprises

- **Digest format is Go-serialization-coupled (highest risk).** `ScopeDigest` is SHA-256 over `encoding/json` of an anonymous struct **without json tags**, so keys are `ModelVersion`, `Kind`, `AgentProfile`, … in struct declaration order, while nested model types use their snake_case tags (normalize.go:774-796). Any mismatch fails closed (`approval scope is stale`), silently bricking every stored grant. Equally, grants/audits are persisted as **gob** in bbolt (store/codec.go) — a Rust rewrite must either bit-compatibly read gob+bbolt or ship a migration; both are external bytes-on-disk contracts.
- **Policy denials are never audited.** In all three executors the audit `defer` is registered only *after* authorization succeeds (http.go:70-91, git.go:118-172, ssh.go:58-89), so `denied` outcomes from `Authorize*` leave no audit record even though `denied` is a defined error class; `denied` is only persisted for later failures (e.g. redirect re-authorization). A naive Rust port that audits denials would observably diverge (extra rows in `capability_audits`).
- **`MaxRedirects` is the one limit with no default.** Zero means "deny all redirects" while zero for timeout/bytes/concurrency means "apply default" (model.go:182-185, normalize.go:128-161). The redirect check is `len(via) > MaxRedirects`, so 0 rejects the first redirect.
- **Shared types cross executor boundaries in observable ways.** `responseLimitError` ("HTTP response exceeds its byte limit") is reused for SSH download overflow, and the git/ssh `output-limit` error text is `process output exceeds its byte limit`; error *texts* surface through the broker's 403 `{"error": ...}` envelope and MCP `isError` content verbatim, so they are contract strings.
- **Subtle fail-closed edge cases a port could invert:** `git config --get-regexp` exit code 1 is treated as "no overrides present" while any other error denies (git.go:100-116); grants are re-read twice around concurrency-slot acquisition (TOCTOU window deliberately narrowed, broker.go:242-332); concurrency for git-over-SSH charges both capabilities; `/v1/tools/list` requires a *bound* token (authentication requires `SessionID != ""`, broker.go:382), so an injected-but-unbound token cannot even discover tools; the broker descriptor contains no secret — all authority is the env-injected bearer token, validated against env-fenced project/generation (broker_server.go:271-288).
- **Doc vs code:** threat model (line 5) says interactive-shell grants "are rejected during normalization" — true, but the code rejects them in *three* places (normalize.go:502, broker.go:315, ssh.go:176); all three error strings differ and are observable. Doc says audits are "bounded … metadata only" — accurate, and pinned by a raw-database canary test (audit_test.go:15). No material doc/code contradictions found.
- **Out-of-scope surfaces this subsystem depends on** (owned by other inventories but part of the observable chain): env injection of `PTRACK_CAPABILITY_*` in `internal/gui/terminal.go:467-470` / `linked_launch.go:112-115`, the Settings Wails methods `PreviewCapabilityV2`/`EnableCapabilityV2`/`SaveCapabilityV2` in `internal/gui/capability_settings.go`, and the `ptrack capability call|mcp` CLI in `internal/cli/capability.go` (reads `PTRACK_CAPABILITY_TOKEN`, enforces `ValidateSessionEnvironment`).
