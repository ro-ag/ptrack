## Notes / surprises

- **Asymmetric error tolerance is the biggest reimplementation trap** (GIT-012): `worktree list`, remote `config`, and both `log` calls may fail without failing Capture (degrading to `worktreesIncomplete`/empty lists), while `status`, `for-each-ref`, and `rev-list` failures are fatal. Timeout/output-limit/cancellation errors are fatal everywhere. Matching this matrix exactly matters more than matching happy-path output.
- **`filesChanged` can under-report**: changed paths are truncated to 500 per commit *before* counting, so a commit touching 600 files reports `filesChanged: 500` (snapshot.go:486-497). Looks like a bug; it is the observable behavior.
- **Worktree `total` counts only live directories**: entries whose root vanished are dropped before `total++` (worktree.go:207-216), so `worktreeBounds.total` is not the raw `git worktree list` count.
- **`isMutatingGitSubcommand` is dead production code** (snapshot.go:552-560) — referenced only by tests as a guardrail asserting Capture stays read-only. A Rust port needs the guarantee, not the function.
- **Report Markdown formats are only substring-pinned by tests** — headings, placeholder strings (`_none_`, `_(unset)_`, `_no matches_`), the `·`-separated inventory line, em-dash in `# Board —`, and the `%q`-quoted search header are observable bytes that need golden fixtures for parity; same for the guide body literal (GDE-006).
- **Search asymmetry**: issues match on title OR body, notes match on body only, milestones/plans/tasks on title only (views.go:188-241). Note `kind` is never searched.
- **Env scrub is broader than the override list**: *all* inherited `GIT_*` variables are removed (runner.go:106-108), not just the dangerous ones — a port that only overrides the five documented vars would behave differently under e.g. `GIT_CONFIG_GLOBAL`.
- **stderr is captured but never surfaced** (GIT-006) — diagnostic detail from failing git commands is dropped by design; errors only carry the exit status via `git command failed: exit status N`.
- **Aggregate budget counts commands before running** (snapshot.go:120-123), so the 9-command cap is on attempts; actual Capture issues 7–9 commands depending on upstream presence (divergence + unpushed are conditional).
